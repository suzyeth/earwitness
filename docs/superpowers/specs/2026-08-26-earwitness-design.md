## 1. Positioning

> **Earwitness** *(n.)* — a witness who testifies to what they heard.

Earwitness is an independent verification layer for phone-call agents. It re-derives what
actually happened on a call **from transcript evidence alone**, and never trusts the
provider's own self-report.

It is deliberately **provider-neutral**. CALL-E is the first and only implemented provider.
This is a measurement tool offered to the phone-agent ecosystem, not a review of any one
vendor.

## 2. Problem statement

Anyone operating a phone agent today judges "did this call succeed?" by reading a boolean
the provider returned. That boolean is not trustworthy.

**This is not hypothetical. It was observed on the first call this project ever placed.**

Probe call `call_YeJC_98WIgQvG6IbCmhrQA` (2026-08-26, recorded verbatim in
`fixtures/probe-01-dtmf-zoom.json`) dialed a Zoom PSTN bridge and was instructed to enter a
meeting ID on the keypad. The complete 18.3-second transcript:

```
 0s  bot   "I'll begin by delivering the opening content."
 3s  user  "Welcome to Zoom. Enter your meeting ID followed by pound."
 5s  bot   "The IVR is asking for the meeting ID followed by pound."
 8s  bot   "I need to send the DTMF tones as specified in the task: 1234567890 followed by #."
       -- call ends, no further response from the bridge --
```

No tones were sent. The bridge never answered again. The task was not performed.

The API reported:

```json
{
  "status": "completed",
  "task_completed": true,
  "completion_confidence": { "score": 0.87, "label": "high" },
  "failure_code": null
}
```

A call with zero output was reported as a clean success at 87% confidence. The same JSON's
own `summary` field simultaneously states the test did not complete — the judging layer
contradicts itself inside a single response.

Two distinct costs follow:

- **Competence.** Operational metrics built on provider self-report are built on sand. A
  reported 90% completion rate may really be 60%.
- **Compliance.** Placing AI calls to consumers in 2026 carries real legal exposure — AI
  identity disclosure, recording consent, TCPA. There is currently no way to *prove* that
  call #4,192 disclosed before asking a substantive question, because the only artifact is
  a boolean that demonstrably lies.

Of the ~30 projects already in `awesome-phone-call-agents`, every one solves *placing* a
call. None solves *knowing whether it worked*.

## 3. Core primitive: the call assertion

The system has exactly one concept: **you declare what must be true of a call; Earwitness
adjudicates it from evidence.**

Every verdict must cite transcript spans. A verdict without evidence is a bug, not a pass.

### Assertion vocabulary (deliberately small)

| Assertion | Failure mode it catches | Provenance |
|---|---|---|
| `disclosed_ai_before_first_question` | Identity disclosure lands after a substantive question | US state AI-disclosure statutes |
| `never_leaked_instructions` | Agent reads its own task prompt aloud | **Observed in probe-01** |
| `grounded(field)` | A structured field has no transcript span where the callee actually said it | Hallucinated extraction |
| `no_human_burn` | Requested a human transfer when told not to | Cost, and burning strangers' time |
| `terminated_cleanly` | Hung up before the task was done | **Observed in probe-01** |
| `self_report_matches_evidence` | Provider's `task_completed` disagrees with the evidence verdict | **Observed in probe-01** |

`self_report_matches_evidence` is the heart of the product. Aggregated across runs it
yields a provider-level metric: *your provider's self-assessment disagreed with the
evidence on K of N calls.* Nothing in the ecosystem measures this today.

## 4. Two input modes, one engine

```
  audit mode : calls the agent already placed  ----+
                                                   |
                                                   +--> assertion engine (pure)
                                                   |          |
  test mode  : calls placed from a scenario  ------+          v
               matrix, on purpose                       Verdict[] + evidence
                                                               |
                                                               v
                                          scorecard / regression diff / CI gate
```

Same assertions, two thin adapters. This is one product, not two.

## 5. Architecture

```
policy.yaml -> schema (Zod) -> planner -> runner -> CALL-E adapter
                                            |
                                            v
                                      CallRecord   (provider-neutral)
                                            |
                                            v
                                        engine/    pure functions, no network,
                                            |      no provider deps
                                            v
                                  Verdict[] + evidence spans -> report
```

Layer flow mirrors the `gacha-simulator` contract already in use:
`schema -> adapter -> pure engine -> reporting`.

### Hard invariants

1. **Engine purity.** `engine/` accepts a `CallRecord` and returns `Verdict[]`. It performs
   no I/O, imports nothing provider-specific, and contains only pure functions.
2. **Evidence or nothing.** Every `Verdict` carries `evidence: TranscriptSpan[]`. A verdict
   that cannot cite spans must return `inconclusive`, never `pass`.
3. **Never read the provider's verdict as input.** `task_completed` and
   `completion_confidence` enter the engine only as *data to be adjudicated against*, never
   as a signal that shortcuts adjudication.

Invariant 1 has a decisive practical consequence: **the entire engine test suite runs on
recorded transcript fixtures and consumes zero phone calls.**

### Two-tier adjudication

Invariant 1 forbids I/O, but assertions like `disclosed_ai_before_first_question` require
semantic judgment that realistically needs a language model. These are reconciled by
splitting adjudication in two:

- **Tier 1 — deterministic.** Computed by pure code with no external help: turn ordering,
  timing, premature termination, self-report mismatch, and literal span matching for
  `grounded()`. `terminated_cleanly` and `self_report_matches_evidence` are Tier 1, which
  means the probe-01 finding is reproducible with no model in the loop at all.
- **Tier 2 — semantic.** The engine calls an **injected `Judge` interface**
  (`(question, spans) => Judgement`) supplied at the boundary. The engine's own code stays
  pure; in tests the judge is a stub replaying recorded judgements, so fixtures stay
  deterministic and offline.

This mirrors the injectable-interface pattern already used in `nativelist`. It also keeps
the most damning assertions model-free, which matters for credibility: the headline claim
does not rest on one LLM's opinion.

### Core types (sketch)

```ts
type TranscriptSpan = {
  offsetSeconds: number
  speaker: 'agent' | 'callee'
  text: string
}

type CallRecord = {
  id: string
  provider: 'calle'
  placedAt: string
  durationSeconds: number
  transcript: TranscriptSpan[]
  structuredResult: unknown | null
  providerSelfReport: { taskCompleted: boolean | null; confidence: number | null }
}

type Verdict = {
  assertion: string
  result: 'pass' | 'fail' | 'inconclusive'
  evidence: TranscriptSpan[]
  rationale: string
}
```

## 6. Callee policy (ethics)

**The system under test is the outbound agent, not the person answering.**

Therefore every demo and test call is directed at a **public automated answering service**
(conference dial-in bridges, automated information lines). Consequences:

- No stranger is called; no human agent's time is consumed.
- No controlled phone number is required, which sidesteps the operator's own reachability
  constraints entirely.
- Runs are reproducible, because the callee is a deterministic machine.

`ETHICS.md` will state this policy explicitly. The submission repository lists "safety by
default" as one of three acceptance criteria, so this is a scoring asset rather than a
caveat.

## 7. Scope

**In:**

- `policy.yaml` declarative assertions, validated by a Zod schema
- Pure assertion engine with fixture-based tests
- CALL-E provider adapter placing real calls at runtime (`POST /v1/calls`, poll, normalize)
- CLI: `earwitness audit <call_id>` and `earwitness run policy.yaml`
- Scorecard: terminal output plus a single-file HTML report
- Regression diff: compare two scorecards and report which assertions changed verdict
- Submission as `apps/typescript/earwitness` plus an `earwitness-audit` Agent Skill

**Out (YAGNI):**

- Web dashboard
- Any second provider implementation (interface only)
- LLM-generated persona matrices — scenarios are authored in the policy file, which is
  cheaper and more reproducible

## 8. Verified platform facts

Established by direct probe on 2026-08-26, not read from docs:

- Base URL `https://api.heycall-e.com` is real; the OpenAPI contract's "Placeholder" label
  is stale. Auth is `Authorization: Bearer <key>`; keys are prefixed `iams_live_`, not the
  documented `calle_live_`.
- **No DTMF capability exists.** Zero hits for `dtmf|keypad|digit|tone|press` across the
  entire OpenAPI contract, corroborated by probe-01's live failure. Keypad IVR trees cannot
  be navigated.
- `recipients` is an array — fan-out to multiple numbers is native.
- `transcript_turns` is returned per attempt. This is the substrate Earwitness runs on.
- `Idempotency-Key` on create makes retries safe.
- Local lines: US, SG, MY, IN, UAE, AU, MX, BR. International (labelled by CALL-E as
  "primarily intended for testing"): UK, CA, DE, JP, FR and roughly 20 more. **Mainland
  China is not supported at all.**
- Observed anomaly, unconfirmed: `created_at` returned six days behind true wall-clock time.

## 11. Risks

| Risk | Mitigation |
|---|---|
| Judges read this as an attack on the host | Provider-neutral framing throughout; ship a measurement tool, never a scorecard of CALL-E |
| Assertion adjudication is itself LLM-based and therefore fallible | Every verdict must cite spans; `inconclusive` is a first-class result; fixtures pin expected verdicts |
| Schedule collision with agentic-cinema (2026-09-07) | 12 days to that deadline, 19 to this one. Engine plus fixtures are buildable without calls and can be interleaved |
| Free-call exhaustion | Fixture-driven tests; additional calls requestable via the hackathon form |
